# 论文速读：TTT-Bench-A-Benchmark-for-Evaluating-Reasoning-Ability-with-Simple-and-Novel-Tic-Tac-Toe-style-Games

## 一句话总结
本文提出了 TTT-Bench，一个包含四种新型 Tic-Tac-Toe 风格双人游戏的基准，用于评估大推理模型（LRM）在基础战略、空间和逻辑推理方面的能力；实验发现，在数学难题上表现优异的模型在这些对人类而言极其简单的直觉任务上反而显著退步。

## 研究问题与动机
1. 现有推理基准高度集中在数学/STEM领域，LRM 在更广泛推理域（战略、空间、逻辑）的能力缺乏系统评估。
2. 已有少数使用棋类游戏评测 LLM 的工作（如 GameBench、UNO Arena 等），但所用游戏早已存在于文献和网络中，训练数据污染风险高，可靠性存疑。
3. 一个核心未解问题：在复杂数学问题上表现出色的 LRM，能否在无需专门知识、仅需基本直觉推理的简单双人策略游戏中做出正确决策？
4. 人类儿童可本能完成的"预判对手、阻断威胁、规划多步战略"等推理能力，在 LRM 中是否同样鲁棒？

## 核心贡献（创新点）
1. **提出 TTT-Bench 基准**：构建四种新型 Tic-Tac-Toe 风格游戏（oTTT/dTTT/cTTT/sTTT），以可验证的文本化棋盘问题测试 LRM 的空间、战略与逻辑推理；与已有基准的本质区别在于游戏形态新颖且从未在网络公开，从根本上避免训练数据污染。
2. **程序化自动生成 pipeline**：基于启发式算法枚举所有合法棋盘状态，过滤掉已胜/已形成 Winning Fork 的状态，仅保留具有确定性最优下一步的问题，确保答案可机械验证；与现有依赖人工标注或蒙特卡洛采样的基准相比，该方法可扩展且零污染。
3. **揭示 LRM 在简单直觉任务上的系统性缺陷**：发现擅长 MATH 500/AIME 2024 的模型在 TTT-Bench 上平均分别低 41% 和 5%，并且"越大模型+更长思维链"并未带来相应收益，反而出现过度思考（overthink）与循环推理现象；这一发现修正了"推理能力随规模单调提升"的朴素假设。
4. **开源 412 道可验证评测题与评估代码**：以 Apache 2.0 许可发布，并为后续研究者提供可直接复用的自动化问题生成工具；对比其他基准的封闭性，本文在可复现与可扩展性上更具开放性。

## 方法详解
1. **四种游戏定义**
   - **oTTT**：标准 3×3 井字棋，三连一线即胜。
   - **dTTT**：两个相邻 3×3 网格共享 C/F/I 三点，任一格内三子成线即胜。
   - **cTTT**：两个相邻立方体共享 B/C/G/F 四点，任一方块面上四贴纸共面即胜。
   - **sTTT**：5×5 格点网，形成边长为 1 的单位正方形或边长为 √2 的对角正方形（四子共顶点）即胜。
2. **自动化问题生成流程（Algorithm 1）**
   - 枚举所有合法棋盘状态（已进行 N 步后）；
   - 过滤条件：① 当前玩家未胜、对手未胜；② 未形成"Winning Fork"（即一方已同时拥有两个一回合即胜的威胁）；
   - 对剩余状态调用启发式求解器判定下一步最优解及判据（Verdict）。
3. **三种 Verdict 分类**
   - **Win**：当前步直接达成获胜条件。
   - **Blocked**：当前步阻断对手的立即获胜威胁。
   - **Fork**：当前步为自身构建两个及以上一回合即胜的潜在赢法，确保未来必胜。
4. **数据集规模与参数**
   - oTTT: N ∈ {4,5}；dTTT: N ∈ {6,7}；cTTT: N ∈ {5,6,7}；sTTT: N ∈ {6,7}；
   - 每种游戏约 100 题，共 412 题，包含单解与多解情形，覆盖 Win/Blocked/Fork 三类判据分布。
5. **评估协议**
   - Pass@1 指标：生成 k=16 条响应（temperature=0.6, top-p=0.95, 28k tokens），按正则提取最后 \boxed{} 答案，多解时任一正确即计为正确。
   - 前沿闭源模型仅生成 1 次响应（受 API 限制）。
   - 硬件：AMD Instinct MI300X GPU；框架基于 DeepScaler 和 VeRL。

## 实验与结果
1. **评测模型谱系**：涵盖 DeepSeek-R1-Distill 系列（1.5B–32B）、S1.1 系列（1.5B–32B）、EXAONE-Deep（2.4B–32B）、QwQ-32B/Preview、OpenThinker2、Light-R1、LIMO、Sky-T1 等 20+ 模型，以及闭源前沿 o3-mini-medium 与 DeepSeek-R1。
2. **整体对比（Pass@1）**
   - 相较 MATH 500：TTT-Bench 平均 ΔPass@1 = **-41.36%**（所有模型在所有四项任务上均显著低于 MATH 500）。
   - 相较 AIME 2024：TTT-Bench 平均 ΔPass@1 = **-4.88%**（oTTT 略优于 AIME，平均 +8.56%，其余三项显著落后）。
3. **各游戏难度排序**（由易到难）：oTTT < dTTT < sTTT < cTTT（与空间约束复杂度与可选落子数正相关）。
4. **Top 模型表现**
   - QwQ-32B：oTTT 92.0%、dTTT 78.1%、cTTT 60.1%、sTTT 60.1%（MATH 500 95.0%，AIME 79.2%）。
   - EXAONE-Deep-32B：oTTT 89.1%、dTTT 71.3%、cTTT 51.5%、sTTT 60.4%（MATH 500 94.9%，AIME 70.0%）。
   - o3-mini-medium：oTTT 79.6%、dTTT 83.0%、cTTT 52.2%、sTTT 75.0%（MATH 500 97.3*，AIME 79.6*）。
   - DeepSeek-R1：oTTT 88.9%、dTTT 72.0%、cTTT 58.9%、sTTT 75.8%（MATH 500 97.3*，AIME 79.8*）。
5. **按 Verdict 分类的性能**：所有模型在 **Win** 类问题上表现最佳；**Blocked** 次之；**Fork** 类问题最差（例如 QwQ-32B 在 sTTT Fork 上仅 36.8%）。cTTT 在三种判据上均低且接近。
6. **思维链长度反常**：TTT-Bench 平均响应长度高于 MATH 500，却远低于 AIME 2024，但准确率反而更低——说明模型对简单任务使用了"过长的无效思考"； larger models 以**更短**的 COT 在 TTT-Bench 上取得更高成绩。
7. **错误模式**：模型倾向于选择"阻断对手 fork"的保守走法，而非"为自己构建 fork 确保必胜"的进攻性最优解；思维轨迹中出现大量循环、无结论的重复推理。

## 相关工作脉络
1. **MATH 500 / AIME 2024 / GSM8K**：主流 LRM 推理基准，聚焦数学演绎与计算；本文定位为互补——证明仅凭数学高分不足以刻画模型的真实推理鲁棒性。
2. **GameBench (Costarelli et al., 2024)**：基于已有棋类游戏评测 LLM 策略推理；本文的差异在于游戏完全原创且程序化生成，彻底规避污染。
3. **GTBench (Duan et al., 2024)**：从博弈论角度评估 LLM；本文更侧重基础空间/直觉推理而非纳什均衡等高级博弈概念。
4. **UNO Arena (Qin et al., 2024)**：基于 UNO 游戏评测顺序决策；UNO 规则复杂且已有大量在线资源，TTT-Bench 以更简规则凸显基本推理短板。
5. **Zebralogic (Lin et al., 2025)、Planning Benchmarks (Valmeekam et al., 2024)**：指出 LLM/LRM 在规划与直觉推理上的失败；本文与之呼应并进一步量化"数学高分≠简单推理鲁棒"的差距。
6. **Nicer than Humans (Fontana et al., 2024)**：考察 LLM 在囚徒困境中的行为；本文转向具象棋盘空间推理，评测维度更加结构化与可验证。

## 局限性与未来方向
1. **游戏域狭窄**：仅 4 种 TTT 变体，难以覆盖常识规划、物理推理、视觉空间谜题等其他直觉推理形态；结论外推需谨慎。
2. **纯文本表示**：高空间性任务以文本呈现，部分失败可能源于"心理可视化"障碍而非纯推理缺陷；未来需引入多模态棋盘输入。
3. **评估协议不对等**：闭源前沿模型仅单次采样，开源模型 16 次采样，影响跨模型可比性。
4. **未来方向**：扩展游戏种类（含非对称信息、随机性等）、支持视觉输入基准、探究"过长 COT 为何损害简单任务"的机制、开发针对性微调策略以弥合数学推理与直觉推理的鸿沟。

## 研究启发与可借鉴点
1. **程序化生成+启发式过滤的自动化基准构建范式**可直接迁移至其他组合游戏或约束求解任务，低成本获得海量无污染可验证样本。
2. **"ΔPass@1 跨域落差"度量**为发现模型能力盲区提供了简洁指标；后续可在更多对立任务对（如代码生成 vs. 空间推理、符号推理 vs. 常识推理）间复用。
3. **长思维链反而降质的现象**提示：训练数据配比与推理时长控制需要针对任务复杂度做动态调整；可借鉴"最短有效 COT"奖励信号设计。
4. **Fork 类问题作为"长期战略"探针**：其低通过率揭示了 LRM 在多步前瞻上的系统性缺陷；可作为后续模型训练/评测的专项难点。
5. **本团队可结合的方向**：将 TTT-Bench 作为内部"直觉推理压力测试"嵌入模型评测流水线；探索多模态变体（棋盘图像输入）以分离空间可视化与逻辑推理贡献；基于 Verdict 分类设计分阶段 RLVR 奖励函数。

## 关键术语表
**Large Reasoning Models (LRMs)**：经强化学习（如 RLVR）训练、能够生成较长链式思维（CoT）并实现自我反思与回溯的大规模语言模型。
**Pass@1**：从 k 次独立采样响应中取首次正确概率的评估指标，多解问题中命中任一解即判为正确。
**Winning Fork**：当前玩家通过一步可同时制造两个及以上"下一回合即胜"威胁的状态，对手无论走哪步都无法同时封堵。
**Verdict（Win/Blocked/Fork）**：三步判定分类——Win 为直接取胜步，Blocked 为阻断对手即时胜势，Fork 为建立多重未来必胜威胁。
**oTTT / dTTT / cTTT / sTTT**：四种 Tic-Tac-Toe 变体，分别对应标准 3×3 棋盘、双相邻 3×3 共享三点、双相邻立方体四子共面、5×5 格点单位/对角正方形胜利。
**RLVR (Reinforcement Learning with Verifiable Rewards)**：利用可自动判定的答案/过程奖励对 LRM 进行强化学习训练的主流范式。
**Chain-of-Thought (COT)**：模型在输出最终答案前生成的逐步推理文本序列；本文指代 LRM 输出的超长思考轨迹。

## 可复现要素
- **数据集**：TTT-Bench，412 道题，以 Apache 2.0 许可证开源（项目主页 https://prakamya-mishra.github.io/TTTBench）。
- **代码**：评估框架基于 DeepScaler 与 VeRL 代码库；问题生成算法见 Appendix C（Algorithm 1）。
- **权重**：评测涵盖 DeepSeek-R1-Distill、S1.1、EXAONE-Deep、QwQ、OpenThinker、Light-R1、LIMO、Sky-T1 等开源模型；闭源模型使用官方 API。
- **关键超参**：temperature=0.6、top-p=0.95、max tokens=28k、k=16（开源模型）；闭源前沿模型单次采样。
- **硬件**：AMD Instinct MI300X™ GPU。
