# 论文速读：POINTS-Reader-Distillation-Free-Adaptation-of-Vision-Languag

## 一句话总结
本文提出了一种完全自动化、无需知识蒸馏的两阶段框架，通过大规模合成数据预热与基于规则过滤的迭代自改进，训练出仅3B参数的端到端文档转换模型 POINTS-Reader，在表格识别等关键指标上超越 Qwen2.5-VL-72B、Mistral OCR 等大型闭源/开源模型。

## 研究问题与动机
- **高质量标注数据稀缺且成本高昂**：文档转换（尤其含复杂表格、公式、多栏排版）严重依赖人工标注或外部模型生成，难以规模化。
- **现有蒸馏范式存在性能天花板与偏见继承**：学生模型直接拟合教师模型（如 GPT-4o、Qwen2.5-VL-72B）的输出，往往无法超越教师，且会继承漏识别表格、结构错误、幻觉等系统性缺陷。
- **合成数据与真实分布存在鸿沟**：纯合成数据排版人工痕迹重，直接用于微调会导致模型在真实文档上泛化能力不足，但盲目堆量又会引发过拟合退化。
- **缺乏无蒸馏的高质量开源数据**：现有开源文档转换数据集（如 KOSMOS-2.5、OLMOCR 数据集）普遍依赖闭源 API 或外部模型蒸馏，限制了底层的算法创新。

## 核心贡献（创新点）
- **提出无蒸馏的两阶段数据构建与模型适配框架**：摒弃对外部大模型的依赖，通过“合成预热+迭代自改进”实现全链路自动化数据生产与模型进化。
- **设计统一输出格式规范与规则化过滤策略**：将文本/表格/公式分别标准化为 Markdown/HTML/LaTeX，并引入基于传统 OCR 的 F1 过滤、表格结构一致性校验与公式语法检查，实现低成本、高可靠的数据质量筛选。
- **揭示合成数据规模与分布的拐点规律**：实验证明合成数据超过约 80 万条后性能开始下降，首次量化了纯合成数据训练的边界，并验证了 ISS 阶段 bridging 真实分布的必要性。
- **打造轻量级 SOTA 文档转换模型**：POINTS-Reader 仅 3B 参数，在 OmniDocBench 表格指标与 Fox 基准上全面超越 Qwen2.5-VL-72B，并大幅领先 GOT-OCR、Mistral OCR 等专家型 OCR 模型。

## 方法详解
- **统一格式预热阶段（UWS）**：针对文档四类核心元素，制定统一输出规范：纯文本采用 Markdown；表格采用去除 CSS 与缩进的 HTML（解决 Markdown 无法表达合并单元格、LaTeX 格式不统一的问题）；公式采用 KaTeX 规范的 LaTeX（行内用 `$...$`，行间用 `$$...$$`）。使用 Qwen2.5-3B-Instruct 按纯文本、含公式、含表格、多栏布局四类生成文本，经规则过滤后通过 Chrome headless 渲染为图像，每类生成约 20 万条高质量图文对，增量微调基座模型。
- **迭代自改进阶段（ISS）**：将 UWS 模型用于 DocMatix（200万+真实文档图像）推理，生成初始标注后执行三重过滤：
  - **文本过滤**：以 PaddleOCR 输出为参考，统计词频计算 Precision/Recall/F1（公式见原文 Eq.1-3），丢弃 F1 < 0.9 的样本。
  - **表格过滤**：校验输出 HTML 表格的行列单元格数量是否一致，剔除结构非法样本。
  - **公式过滤**：仅检查 LaTeX 语法是否正确，剔除语法错误样本。
  过滤后的高质量数据与 UWS 数据混合，结合 POINTS-1.5 原有通用视觉指令数据，在 8192 最大上下文长度下迭代重训练，形成“模型能力↑ → 标注质量↑ → 训练数据质量↑”的正反馈闭环。
- **训练配置**：基座沿用 POINTS-1.5，预训练阶段数据保持一致，视觉指令微调阶段替换/扩充为新数据；训练耗时约 7 小时（100万样本），推理 200 万 DocMatix 样本约需 10 小时。
