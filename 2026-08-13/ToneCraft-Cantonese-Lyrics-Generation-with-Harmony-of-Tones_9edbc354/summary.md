# 论文速读：ToneCraft-Cantonese-Lyrics-Generation-with-Harmony-of-Tones

## 一句话总结
本文提出 **ToneCraft** 框架，利用大语言模型（LLM）生成与给定旋律音高协调一致的粤语歌词，解决了粤语九调六声系统中声调与旋律对齐的核心难题。该方法无需大量旋律-歌词对齐数据，仅通过逆工程从纯歌词数据中提取调性知识，即可实现高质量粤语歌词生成。

## 研究问题与动机
1. **粤语声调复杂性**：粤语有九个轮廓和六个基本声调，声调差异直接改变词义，歌词必须与旋律音高轮廓对齐才能保证可唱性，避免歧义。
2. **现有方法不足**：当前歌词生成研究多关注音节节奏与旋律的对齐，忽略音高-声调对齐；且大多依赖大量旋律-歌词对齐数据，而粤语歌曲此类数据稀缺。
3. **约束下的多样性保持**：和声规则大幅缩减候选歌词空间，如何在满足对齐约束的同时保持歌词多样性与语义质量是核心挑战。
4. **人类创作参考有限**：人类填词依赖经验规则（如0243方法），难以直接规模化迁移到模型训练中。

## 核心贡献（创新点）
1. **ToneCraft框架**：首个面向粤语歌词生成的LLM框架，实现字符级旋律-声调对齐；与Seq2Seq方法相比，无需对齐数据即可利用LLM生成灵活性和上下文理解能力。
2. **HAC算法（Harmony-Aware Control）**：结合字符级控制、符号旋律引导与任务特定损失（HAL），在保留生成灵活性的同时实现调性和谐；区别于传统固定格式约束方法。
3. **CTP-Mapping方法**：基于0243方法逆工程构建词-调-音映射表，使模型能从纯歌词数据中学习旋律-声调对齐关系，消除对齐数据依赖；可推广至普通话歌词构建。
4. **抛光优化模块**：通过不和谐检测、掩码预测与重排序，局部修正生成的不协调位置，降低歧义并提升可唱性。

## 方法详解
1. **Pitch Mapping（音高映射）**：
   - **A2R-Mapping**：按每句歌词将绝对音高（MIDI 0-127）划分为四个等距相对音高层级。
   - **CTP-Mapping**：基于0243方法建立音高-声调映射表，将旋律音高抽象为四个相对音高类别（P1-P4），反向工程得到纯歌词数据集的"伪对齐"标签。

2. **字符级控制（Character-level Control）**：
   - 引入特殊token `<p0>`~`<p4>` 表示标点和四个相对音高层级。
   - 修改Tokenizer：跳过中文字符的合并，确保每个token对应单个汉字。
   - 修改LM Head：将禁用多字token的logits设为负无穷，强制字符级生成。

3. **Harmony度量**：
   $$
   Harmony = \frac{1}{n}\sum_{i=1}^{n}e^{-|\hat{p}_i - p_i|}
   $$
   衡量预测音高序列与真实音高序列的对齐程度。

4. **Harmony-Aware Loss (HAL)**：
   $$
   \mathcal{L} = -\sum_{i=1}^{N}y_i\log(\hat{y}_i) + \ln\left(1 - \frac{1}{n}\sum_{i=1}^{n}e^{-|\hat{p}_i - p_i|}\right)
   $$
   第一项为标准交叉熵损失，第二项为调性正则项，梯度方向自然驱动预测音高向目标声调靠近。

5. **Mixed Training**：结合歌词数据与BELLE指令数据进行混合微调，通过`fill_num`变量区分任务类型，稳定训练过程。

6. **Polish Process**：
   - 检测偏差≥2层或轮廓冲突的不和谐位置。
   - 掩码整词后用上下文预测替换候选。
   - 基于调和分数 $S_{harm}$ 与上下文连续性分数 $S_{cont}$ 加权重排序，选择最优候选。

## 实验与结果
- **数据集**：Feitsui粤语歌词（6000+首）、 Mandarin歌曲歌词、BELLE指令数据集。
- **基线**：Llama3/Qwen2微调、o3-mini、DeepSeek-R1、SongNet、SmBART-3、人类填词。
- **主要结果**：
  - **Objective**：ToneCraft_Llama3在Harmony指标上达 **0.973±0.005**，显著优于次优模型SmBART-3（0.862）和人类（0.671）；Consistency达0.953，远超所有基线。
  - **Subjective**：ToneCraft_Qwen2(Polished)在Harmonicity（4.11）、Listenability（3.86）、Ambiguity（1.26）三项对齐指标上均排名第一，Fluency（4.03）和Coherence（4.11）亦为最优。
  - **提升幅度**：相比最强Seq2Seq基线SmBART-3，Harmony提升约 **11%**，主观Harmonicity提升 **22%**。

## 相关工作脉络
1. **SongNet / SmBART-3**：采用序列到序列建模，依赖旋律-歌词对齐数据；本文转向LLM架构，通过CTP-Mapping规避对齐数据依赖。
2. **ChipSong / DeepRapper**：关注音节节奏、押韵等约束；本文聚焦音高-声调精细对齐，约束更严格。
3. **Charpoet**：首次引入字符级LLM控制；本文在此基础上进一步引入音高token和HAL损失，适配声调语言。
4. **Songmass / Unilg**：使用模板或伪对齐对减少数据需求；本文通过领域知识（0243方法）逆工程构建映射表，更具可解释性。
5. **S²mile / SongComposer**：多模态歌词生成；本文专注于歌词-旋律对齐这一细分挑战。

## 局限性与未来方向
1. **简化的对齐假设**：当前采用音符-汉字一对一映射，实际歌曲中音符时值与多音节字的影响未被考虑。
2. **缺乏时值建模**：未纳入音符时长信息，限制了节奏层面的对齐优化。
3. **粤语专用性**：虽可扩展至其他声调语言，但CTP-Mapping需针对各语言重新构建。
4. **未来方向**：结合音高与时值联合建模、引入入声等 phonetic 特征、探索跨声调语言泛化。

## 研究启发与可借鉴点
1. **字符级控制+特殊token**：适用于任何需要精细对齐的文本生成任务（如藏语/泰语歌词生成），可通过修改tokenizer实现粒度控制。
2. **领域知识逆工程**：将人类专家规则（0243方法）转化为映射表，从无标注数据中提取"伪对齐"信号，思路可迁移至其他缺乏标注的低资源语言任务。
3. **任务感知的混合训练**：通过`fill_num`等机制动态区分任务类型并选择性应用定制损失，解决多任务训练不稳定的通用方案。
4. **抛光优化模块**：后处理重排序策略可与任何生成模型结合，在不重新训练的情况下局部提升质量。
5. **HAL损失的梯度分析**：证明其能驱动音高向目标声调收敛，该分析范式可用于设计其他结构感知的正则项。

## 关键术语表
- **Harmony（和声）**：本文特指歌词声调轮廓与旋律音高轮廓的对齐程度，非音乐学和声学中的chord概念。
- **0243方法**：粤语填词经典规则，将旋律分为四个相对音高（Do/Re/Mi/Fa），指导选词使声调与音高匹配。
- **CTP-Mapping**：Char-Tone-Pitch Mapping，基于0243方法构建的词-调-音映射表，用于逆工程提取对齐信号。
- **A2R-Mapping**：Absolute-to-Relative Mapping，按四分位数将绝对MIDI音高划分为四个相对音高层级。
- **Harmony-Aware Loss (HAL)**：融合交叉熵与调性正则项的复合损失，显式优化歌词-旋律对齐。
- **Five-Level Mark（五度标记法）**：赵元任提出的声调记音系统，用1-5表示音高相对级别。
- **Polish Process**：后处理优化模块，通过不和谐检测、掩码预测与重排序修正局部对齐偏差。
